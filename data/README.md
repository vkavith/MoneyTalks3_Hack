# Shared data

Everything here is generated by `scripts/seed.ts`. Do not hand-edit it. To add or change a scenario, the lane 4 owner edits the script, runs `npm run seed` and commits both.

All companies, people and bank details are fictional. The buyer is "Meridian Manufacturing Co."

| File | What it is | Used by |
|---|---|---|
| `vendors.json` | Vendor master file, including the bank details payments go to | lanes 1, 2, 3 |
| `purchase_orders.json` | What was ordered: lines, quantities, prices | lane 2 |
| `goods_receipts.json` | What arrived, per PO line | lane 2 |
| `policy.json` | Price and quantity tolerances, approval limits and tiers, single-payment limit | lanes 2, 3 |
| `bank_statement.json` | Statement lines for reconciliation in mock mode, plus unrelated noise | lane 3 |
| `inbox/INV-000N.pdf` | The invoices as they arrive | lane 1 |
| `expected/captured/INV-000N.json` | Ground truth: what `capture` should return for each PDF | lane 1 tests |
| `expected/outcomes.json` | Ground truth: match outcome, exception codes and resting status per invoice | lane 2 tests, CI |

Load it with the helpers in `@ap/shared/load` (`loadContext`, `listInbox`, `loadCapturedFixture`, `loadExpectedOutcomes`), which validate every file against the schema.
